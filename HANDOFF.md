## 2. Top-level modules (one line each)

- `ai_taksi_data/app/models/` — SQLAlchemy entities, enums, authentication tables and driver offers.
- `ai_taksi_data/app/api/` — FastAPI auth, admin, rider, driver and offer HTTP routes with role dependencies.
- `ai_taksi_data/app/services/` — OTP/SMS, security utilities, pure matching rules and transactional workflow.
- `ai_taksi_data/app/tasks.py` — Celery Beat scheduling and worker task wrappers in Asia/Tashkent time.
- `ai_taksi_data/app/db.py`, `config.py`, `deps.py`, `schemas.py`, `main.py` — DB sessions, configuration, auth dependencies, typed API contracts and HTTP application.
- `ai_taksi_data/alembic/` — Alembic environment and four historical schema/index revisions.
- `ai_taksi_data/scripts/` — demonstration PostgreSQL/PostGIS seed dataset.
- `ai_taksi_data/tests/` — pytest fixtures and HTTP/matching regression tests (SQLite-compatibility setup).
- `ai_taksi_flutter/lib/core/` — client configuration and local-only chat policy.
- `ai_taksi_flutter/lib/data/`, `lib/models/`, `lib/state/` — Dio API client, typed DTOs and Riverpod providers.
- `ai_taksi_flutter/lib/ui/` — Uzbek-first Material 3 screens and shared presentation widgets.
- `ai_taksi_flutter/android/`, `test/` — partial Android manifests and a Dart chat-policy test.
- `docs/` — project brief, competition criteria, concept image, simulation output, exact file inventory and handoff.

## 6. Known bugs, TODOs and blockers (priority order)

1. **P0 — privacy enforcement boundary:** No backend read/write chat API exists; Flutter chat is local-only and its phone/username filter and ±1-hour window cannot guarantee server-side confidentiality. Outside HTTP JSON, infrastructure access logs, monitoring and external proxies need independent redaction and tests. Redaction regexes are not formal guarantees.
2. **P0 — matching concurrency:** Group creation and offer accept/expire/decline can race across workers. No Postgres row locks, idempotency keys or distributed scheduler lock are implemented; `--concurrency=1` reduces but does not eliminate multi-instance races.
3. **P0 — production identity/SMS:** Fake SMS is in memory; Eskiz provider is a stub. OTP rate limits are DB-based and can race under concurrency. Protect real admin provisioning and production secrets before launch.
4. **P0 — deployment verification:** PostgreSQL/PostGIS migrations, seed, indexes and data integrity have never been tested against an actual running PostGIS service here.
5. **P1 — incomplete API/Flutter contracts:** No published route/pickup-point list, rider trip-offer details, active-trip detail, ratings submission or chat API. These Flutter screens are explicit **Namoyish** previews; rider trip-confirm API exists but has no safe live trip IDs from a listing endpoint.
6. **P1 — performance:** Matching rescans drivers and prices per group and lazily reads trip members during offer transitions; added indexes are unbenchmarked; inspect `EXPLAIN (ANALYZE, BUFFERS)` and batch queries.
7. **P1 — incorrect/incomplete planning semantics:** Confirmation GETs still create missing rows for the requesting rider; 10-minute grouping compares arrive-by slots rather than verified pickup ETA; 6-stop seed produces 6 groups but only 2 Damas can serve, leaving 26 riders unmatched.
8. **P1 — driver scoring quality:** Proximity is placeholder 0 km; pickup coordinates and plate/driver identifiers are illustrative fixtures, not verified operational data.
9. **P1 — Android build reproducibility:** Missing full Gradle/Kotlin scaffold and `pubspec.lock`; Flutter version not pinned; manifest preservation and `flutter analyze`/debug APK validation remain essential.
10. **P2 — incomplete operational coverage:** Push delivery is a Celery hook only; no real calls, payments or trip-location tracking. Trip confirmation lacks separate per-rider acknowledgment timestamp/state. These are project roadmap gaps, **not** features added by this handoff.
11. **P2 — documentation freshness:** Some existing READMEs still describe the older 'data layer only' phase, and Flutter README mentions a legacy release cleartext instruction; use the dated engineering audit and actual manifests as source of truth. No source/README edits were made in this handoff.

## 7. Chat-only background, historical decisions and assumptions

- The larger initiative is a **12-slide “Raqamli avlod qizlari”** competition pitch; those 12 generated slide artworks and a PowerPoint were **not in the audited source ZIP** and have not been bundled into the runnable app. The original Nizom and project brief are now included in `docs/` for context.
- UI look was established with a **white/teal, rounded Material design, Uzbek-first** three-screen concept image; the concept image is bundled in `docs/AI_Taksi_Concept.png` as a visual reference, not Flutter UI source or a working prototype.
- Earlier chat described **5,000+ users, 1,000+ trips and 15–20% savings**; these are presentation aspirations, not measured outcomes, and must not be cited as actual product metrics.
- Decisions made during chat: Kosonsoy → NamSU first pilot; six *illustrative* pickup points; 40 demo riders with Monday/Wednesday 13:00 arrive-by schedules; 5 demo drivers (2 Yengil, 2 Damas, 1 Avtobus); exact-stop grouping/10-minute time window; weights 0.35/0.25/0.20/0.10/0.10. Most are documented in backend code and README, but prior discussions and rejected alternatives are not preserved as Git history.
- **FakeSMSProvider** is a running development mock stored only in process memory. **EskizSMSProvider** exists as a nonfunctional stub. The app does *not* send real SMS, and UI/demo chat does *not* communicate with the backend.
- Public planned features such as live GPS map, masked WebRTC calling, FCM pushes, online payments and women-only grouping appear in the specification, but are not proven implemented by the archived app.
- Prior chat reported a one-day simulated match (40 confirmations, 6 groups, 2 offered rides, 26 unmatched); its recorded text is included at `docs/SIMULATION_OUTPUT.txt`, not a DB integration run.
- Previous ZIP releases, conversational code/design decisions, screenshots and tool execution logs are not a Git commit history. This bundle is a clean handoff snapshot only; no Git repository/remote has been created.
